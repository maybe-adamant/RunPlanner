# Published outcomes → recommended native interventions

## Question and evidence

Given the answer the planner actually exports and the inputs the native game
actually accepts, where should each outcome be realized? This is a
recommendation layer over the existing census, not another hook inventory.
It deliberately starts from published products rather than assuming today's
wrapper set is necessary.

Baseline and unresolved findings are in the [audit index](README.md).
The primary export contract is
[`execution-plan/model.ts`](../../../packages/planner-engine/src/execution-plan/model.ts).
Its construction is split between
[`assembly/overview.ts`](../../../packages/planner-engine/src/execution-plan/assembly/overview.ts),
[`assembly/timeline-transactions.ts`](../../../packages/planner-engine/src/execution-plan/assembly/timeline-transactions.ts),
and the adjacent loadout, doors, hub, lifecycle, and diagnostic assemblers.
These are wire products, not editor drafts or the entire simulator state.

Native references name files/functions in the supplied local
`../../1GameData/Scripts` snapshot (relative to repository root), not online
or assumed current game behavior. The existing [World](WORLD.md),
[Acquisition](ACQUISITIONS.md), and [Effects](EFFECTS.md) matrices retain exact
executor registration locations, native caller lines, and test evidence.

Recommendations use:

- **Insert:** copy published data into an existing native construction result
  or forcing argument. The native game still applies it.
- **Select:** constrain the exact native random decision because the published
  answer is not a complete native result or no suitable argument is exposed.
- **Native:** no outcome override; retain binding/coordination/checkpoints
  only where independently needed.
- **Investigate:** a concrete remaining question prevents choosing a smaller
  truthful contact. This is not permission to add a replacement implementation.

“Keep” means keep that intervention shape, not certify every current line or
coroutine lifetime. Recommendations do not authorize edits. None requires a
new engine product or protocol field on the evidence presently established.

Read each recommendation with its disposition: an explicit open question takes
precedence over “Keep.” In particular, condition-override rows are provisional,
and native timing is unverified wherever the lifetime matrix calls for a probe.
Source-supported contact choice, locally tested wiring, and live timing proof
are separate evidence levels; this document establishes only the first unless
a row explicitly cites stronger evidence. It does not reopen settled contacts
just because another theoretical implementation is possible.
