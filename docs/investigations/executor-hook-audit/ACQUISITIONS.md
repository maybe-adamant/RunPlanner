# Acquisition hook audit

Modes: **B** scope/binding; **S** RNG steering; **D** direct outcome insertion;
**C** coordination/checkpoint; **R?** condition/policy intervention requiring
adjudication—not a claim of wholesale native recreation. Mixed hooks list all
roles. See [classification and exception dispositions](INTERVENTION_MODES.md).

Baseline, policy and status definitions: [audit index](README.md).

65 expanded hook registrations across 13 files: 60 textual `wrap` calls, with one registration factory expanded to six NPC functions. All are wrappers; no additional registration mechanism found in this family. Four other acquisition files contain assembly/helpers only.

Evidence is static source plus inspection of existing test definitions. No tests or live game probes were run.

### Findings

1. **Suspected issue: Pom Slice has no entry carrier.** `levels/hooks.lua:13` accepts only `GiftDrop`, and `:290` hardcodes that identity when claiming. `StoreRewardRandomStack` is explicitly modeled with a random-target level resolution in planner `packages/hades2-catalog/src/declarations/rewards/acquisitions.ts:318`; native `ConsumableData.lua:776` declares its `UseStoreRewardRandomStack` callback and threaded arguments at `:788`. The downstream executor callbacks require `__runPlannerTimelineHandle`, injected only through the GiftDrop use path. Generic pickups reject both level resolutions and `UseFunctionName`. The published Pom Slice target/count therefore appears neither steered nor completed. This contradicts the reward audit’s claimed coverage.

2. **Suspected issue: redundant NPC eligibility preflight.** `npc/hooks.lua:29-32,58-76` calls `IsGameStateEligible` on every authored native option before installing it. Native NPC functions already perform this filtering, and the integration boundary prohibits a second offer-legality policy. Furthermore, `npc/hooks.lua:130-138` reapplies the offer without repeating that check, potentially making the early rejection both ineffective and too late for option-specific preparation. This needs a policy-removal disposition, not additional preflight.

3. **Suspected issue: unnecessary visible-Pom `UseLoot` wrapper.** `levels/hooks.lua:129` only saves/sets/restores `__runPlannerLevelCarrier` and reports. A production-wide search finds no consumer of that marker; all references are writes or save/restore operations in this same file. Other marker writes in that file likewise appear dead.

4. **Needs probe: coroutine lifetimes.** Native `TraitLogic.lua:905` dispatches acquired effects through `thread(CallFunctionName, ...)`. Circe/Icarus consume a dynamically active NPC selection, while Echo and ordinary consequential traits retain explicit pending records. The Circe/Icarus native target functions have no initial wait, so source alone does not establish failure. Existing tests exercise nested callback execution rather than proving native scheduler behavior.

### Matrix conventions

Executor paths below are relative to `src/mods/room/timeline/acquisitions/`. Native paths are relative to `../../1GameData/Scripts/`.

- **B**: `room.begin` checks exact-owner prerequisite readiness; a premature bound action becomes passive but still calls native.
- **D**: steering failure is diagnostic, not a semantic acquisition mismatch.
- **C**: completes the published handle and may release local dependents; does not attest selected state.
- **P**: incidental/unclaimed contacts pass through.
- Native exceptions propagate; protected scopes restore temporary state before rethrowing.
- **Confirmed** means the contact follows from static source, not live certification.
