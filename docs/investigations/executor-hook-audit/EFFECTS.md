## Concrete source findings

### F1 — Fig Leaf can steer a native Vow enemy-substitution roll

`keepsakes/fig_leaf.lua:24` scopes the whole spawning function; `:40` consumes its first `RandomChance`, without identifying the Fig Leaf call. Native pre-spawning clears `encounter.CanEncounterSkip` following a failed skip (`G/EncounterLogic.lua:371`). The subsequent ordinary spawning path consequently does not execute the Fig Leaf roll at `:482`, but can call `HandleNextSpawn` at `:645`; that function rolls `NextBiomeEnemyShrineUpgrade` at `:788`. The fresh scope can therefore force that unrelated roll to the published `figLeafSkip` value. This is a concrete nested-call source path, separate from coroutine scheduling uncertainty. Actual live execution of this combination has not been demonstrated. `tests/keepsakes/test_encounter_effects.lua:18` models the first arbitrary roll as Fig Leaf and does not cover this no-Fig-roll path.

### F2 — Anvil and Well Twist scopes can continue realization after a prerequisite mismatch

`room/timeline/transformations/use.lua:43` obtains a bound payload with `peek`, then arms Anvil/Twist at `:58–61`. Readiness is enforced only when `ConsumableUsedPresentation` calls `room.begin` at `:87`. If that exact bound transaction has unmet prerequisites, the session becomes passive, but the already-armed scopes remain. Neither Anvil’s `RemoveRandomValue` wrapper (`anvil.lua:27`) nor Twist’s `GetRandomValue` wrapper (`well_twist.lua:27`) checks synchronization or acceptance. Native ordering is definitive: `G/InteractLogic.lua:1014` invokes accepted presentation; `:1101` invokes the actual transformation afterward. These later selectors can still force the authored outcome after enforcement should stop. Existing tests at `tests/room/test_transformations.lua:360` and `:389` cover successful acceptance, not failed `begin`. This is source-supported analysis, not a newly executed reproduction.

### D1 — Starting admission authority wording is stale

`docs/design/GAME_INTEGRATION_BOUNDARY.md` says the plan freezes at nested `EquipKeepsake`. Current code freezes it before native `CreateNewHero` (`loadout/hooks.lua:65–79`), permitting starting-Hex realization. `tests/loadout/test_session.lua:80` explicitly witnesses that behavior. This is a documentation conflict, not evidence that the newer runtime behavior is wrong.

## Bounded probes, not established defects

- Coroutine interleaving: whole-function mutable scopes, especially Fig Leaf across native waits, need actual host scheduling proof. The source-supported F1 nested-call path does not depend on interleaving.
- Starting/rack immediate equip scope versus threaded acquire dispatch: native `TraitLogic.lua:905` uses thread; replay accommodates delayed callbacks, ordinary equip does not. Need actual scheduler witness before calling it broken.
- Scope-wide selectors (equip array selector, Twist GetRandomValue, Hex layout selector) need nested incidental-contact witnesses. Intended source calls are verified; in-game isolation is not fully proven.
- Anvil’s forced RemoveRandomValue returns without removing the value. Current call sites discard/rebuild these tables, so no present semantic divergence established; helper-contract fragility only.
- Required Destroy is engine infrastructure with exact Lua call-site evidence, not a Lua body available for deeper audit.
