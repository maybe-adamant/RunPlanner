# Thread and deferred-lifetime dispositions

Companion to the [registration census](REGISTRATIONS.md), [world](WORLD.md),
[acquisition](ACQUISITIONS.md), and [effect](EFFECTS.md) matrices. Those matrices
own exact registration locations and source traces. This document adds the
necessity challenge; it does not approve existing scopes merely because they
work in synchronous tests.

## Review rule

Acquired-effect source disposition: `Main.lua:thread` immediately resumes the
new coroutine; only an actual yield releases the caller. Ordinary equip and
Circe/Icarus selectors precede such yields, so their scopes are retained. The
rows below record the original scheduling questions, not proof of deferred
first dispatch. Echo BBB does wait before its nested menu: its retained result
is now restricted to the native `SelectEchoBoon` menu and transferred to that
menu before native handling. A coroutine witness exercises both waits with an
unrelated menu between them. Live interleaving frequency remains unmeasured.

### Accepted corrections to the baseline rows

The tables below retain the inspected baseline and original questions. Current
source-backed dispositions are:

- Mystery consumes construction context at `GiveLoot` and binds its returned
  provider. The separate `CreateLoot` wrapper is removed; later unwrap animation
  has no construction context.
- Spell/Path retain their native provider/item-bound screen stacks. Hex tree
  construction consumes the expected spell-trait identity before native tree
  generation, so presentation waits cannot extend the tree override.
- Ship wheel generation scope retires at the final preview. Native wheel
  identity survives until accepted use, which publishes its continuation before
  native notification immediately resumes encounter setup.
- Refills begin at `FillInShopOptions`, after native purchase checks. World
  restock context is invocation-local through its screen wait and retry, then
  retires on native return. Unowned/denied refills bypass initial inventory
  forcing. Well/Shrine selectors remain construction-local.
- Nemesis family/free-item preparation only peeks. Accepted trait exchange
  carries its owner on the exact outer dialog screen to native exchange return;
  the global next-removal observer is removed. Free drop begins at its exact
  source, and contest begins at setup with a source-bound timer terminal.

These are verified with focused source-backed coroutine and adapter witnesses,
not live-game scheduling claims. Condition-override questions remain separate.

Use [OUTCOME_INTERVENTIONS](OUTCOME_INTERVENTIONS.md) to choose the native seam.
This document evaluates only the context lifetime that seam needs. A justified
selector scope is not a mandate to keep that selector if a simpler supported
input is established; two hooks are not a defect merely because there are two.

For every hook that retains context across native dispatch, a yield, a menu,
or a later callback, record:

1. The native boundary and all participating registrations.
2. What a single intervention could receive and steer.
3. The specific missing information or later decision that prevents that
   single point from sufficing. If none is established, say so.
4. The smallest retained context and its intended terminal; distinguish this
   from what the current implementation actually retains.
5. Whether native continuation, interleaving, repeated calls, exceptions, and
   passive-session cleanup are proven or still need a witness.

**Split justified** means distinct contacts have distinct necessary jobs. It
does not certify their current lifetime implementation. **Narrow scope only**
means a selector needs its immediate caller's context, not a thread-spanning
transaction. **Unproven** means the extra lifetime has not earned acceptance.
**Unnecessary** identifies a discovered path with no consumer. Multiple rows
for the same native name refer to different wrappers; do not merge their
ownership. A function invoked with `thread` may still need only one local hook.

## Acceptance of a lifetime claim

These dispositions supplement every currently identified threaded, yielding,
or deferred chain in the family matrices; they are not a claim that static
inspection proves every transitive host call non-yielding. Registrations outside
these chains remain ordinary local contacts unless a native caller trace shows
otherwise. New evidence must update both the owning matrix and this disposition.

For an unresolved chain, the next useful witness is native ordering evidence:
entry, dispatch/return, yield/resume, exact selector, and scope retirement,
including an unrelated call while suspended where applicable. Synchronous
nested stubs establish payload plumbing, not coroutine safety. Do not add a
generic thread framework merely to make these tests pass. No source behavior
was changed and no live scheduler claim was tested in this documentation pass.
